1. 객체 탐지

real model

IDEA-Research/grounding-dino-base

입력원본 이미지 + UI 탐지 쿼리
person. car. door. light. shadow.
처리Transformers zero-shot object detection. 사용자가 지정한 query에 대해 box/text threshold 0.25 적용
출력DetectedObject[] + 박스가 그려진 이미지

2. 장면 감독

real model

google/gemma-4-12B-it, HF cache local only

입력원본 이미지 + detector 객체 요약
처리Multimodal chat prompt로 JSON만 생성하도록 지시
출력장면 분석, 장르, 제목, 로그라인, 대본, 포스터 prompt, TTS text

3. 포스터 생성

real model

Tongyi-MAI/Z-Image-Turbo, 512x768, 9 steps

입력Gemma poster_prompt, 제목, 장르, 로그라인, 선택 레퍼런스
처리Z-Image-Turbo 직접 생성. 제목 텍스트도 프롬프트로 모델에 요청
출력영화 포스터 이미지. 레퍼런스는 색감 prompt hint로 사용

4. 음성 합성

real model

Qwen/Qwen3-TTS-12Hz-0.6B-Base

입력Gemma tts_text, UI 출력 언어, UI 음성 모드, voice_reference/yanghoon_ref.wav + transcript 또는 기본 speaker
처리클론 선택 시 Base 모델의 generate_voice_clone() 호출. 기본 목소리 선택 시 CustomVoice/Ryan 호출. TTS language는 UI 출력 언어와 동기화
출력선택한 언어/음성 모드의 WAV 파일 경로

실행 순서와 메모리 처리

  1. image.convert("RGB"), 레퍼런스도 있으면 RGB 변환
  2. Detector 실행 후 객체와 boxed image 확보
  3. 각 GPU 모델 단계 뒤 del adapter와 torch.cuda.empty_cache() 수행
  4. Gemma가 구조화된 trailer concept 생성
  5. Z-Image-Turbo가 제목 포함 poster를 직접 생성
  6. Qwen3-TTS는 별도 프로세스로 WAV 생성 후 종료
  7. 모든 상태를 PipelineDiagnostics로 렌더링

완료된 데모 핵심
  • 이미지 1장 → 탐지 → 장면 분석 → 포스터 → 음성까지 end-to-end 성공
  • 각 단계 fallback으로 발표 중 앱 정지 방지
  • Gradio UI에서 레퍼런스 포스터 선택 입력 추가됨
주의할 점
  • Gemma는 local_files_only=True라 캐시가 없으면 실패
  • Qwen3-TTS 1.7B VoiceDesign은 RTX 5090 32GB에서 OOM 확인, 현재 0.6B 사용
  • 포스터 레퍼런스는 엄밀한 style transfer가 아니라 palette/style hint
남은 품질 리스크
  • Z-Image-Turbo가 제목 철자나 포스터 타이포그래피를 불안정하게 생성할 수 있음
  • 탐지 prompt가 고정이라 이미지에 따라 객체 후보가 제한될 수 있음
  • 첫 실행은 모델 로딩/캐시 상태에 따라 지연이 늘어날 수 있음

검토자가 기억해야 할 한 문장

이 구현은 “한 장의 이미지를 근거로 Gemma가 영화 콘셉트를 쓰고, Z-Image-Turbo가 제목 포함 포스터를 직접 만들며, Qwen3-TTS가 영어 예고편 내레이션을 읽는” 순차형 라이브 데모 파이프라인이다.
